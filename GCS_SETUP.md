# KIRA — Google Cloud Storage Setup Guide

This document explains how to set up Google Cloud Storage and configure KIRA from scratch.

---

## Architecture Overview

```
Browser (React/Vite)
       │
       │  Firebase ID Token (Authorization: Bearer <token>)
       ▼
  Express Backend (Node.js)
       │  ├─ Verifies token via Firebase Admin SDK
       │  ├─ Calls @google-cloud/storage SDK
       │  └─ Reads/writes file metadata in Firestore
       ▼
  Google Cloud Storage Bucket (private)
       │
       └─ File objects organized as:
          users/{userId}/{category}/{uuid}-{safeFilename}
```

For **large files** (>=10 MB), the flow is:
```
Frontend → Backend (request signed URL) → GCS SDK generates PUT URL
Frontend → PUT file directly to GCS (no backend bandwidth used)
Frontend → Backend (confirm-upload to save metadata in Firestore)
```

## Part 1 — Google Cloud Project Setup

### 1.1 Create or Select a Google Cloud Project

1. Go to https://console.cloud.google.com
2. Click the project dropdown → **New Project**
3. Give it a name (e.g., `kira-storage`) and click **Create**
4. Note your **Project ID** (used in env vars)

### 1.2 Enable the Cloud Storage API

1. In your project, go to **APIs & Services → Library**
2. Search for **Cloud Storage** → click **Cloud Storage JSON API**
3. Click **Enable**

### 1.3 Create a GCS Bucket

1. Go to **Cloud Storage → Buckets → Create**
2. Choose a globally unique bucket name (e.g., `kira-files-prod`)
3. **Region:** Choose closest to your users (e.g., `us-central1` or `asia-south1`)
4. **Storage class:** Standard
5. **Access control:** **Uniform** (recommended — do NOT enable public access)
6. **Public access prevention:** Enforce — this keeps the bucket private
7. Click **Create**

> IMPORTANT: Never make this bucket publicly accessible. All access goes through signed URLs generated by the backend.

### 1.4 Configure CORS on the Bucket

CORS is required to allow the frontend to PUT files directly to GCS via signed URLs.

Create a file `cors.json`:

```json
[
  {
    "origin": ["http://localhost:5173", "https://your-production-domain.com"],
    "method": ["GET", "PUT", "POST", "DELETE", "HEAD"],
    "responseHeader": ["Content-Type", "Authorization"],
    "maxAgeSeconds": 3600
  }
]
```

Apply it with the Google Cloud CLI:

```bash
gcloud storage buckets update gs://YOUR_BUCKET_NAME --cors-file=cors.json
```

## Part 2 — Service Account Setup

### 2.1 Create a Service Account

1. Go to **IAM & Admin → Service Accounts → Create Service Account**
2. Name it `kira-backend`
3. Click **Create and Continue**

### 2.2 Grant IAM Roles (Least Privilege)

| Role | Purpose |
|------|---------|
| `Storage Object Admin` (bucket-level) | Upload, download, delete, list objects |
| `Firebase Admin SDK Administrator Service Agent` | Verify Firebase Auth tokens |

To grant bucket-level access:
1. Go to **Cloud Storage → Buckets → your-bucket → Permissions**
2. Click **Grant Access**
3. Add your service account email
4. Role: **Storage Object Admin**

### 2.3 Create a JSON Key

1. Go to **IAM & Admin → Service Accounts → your service account**
2. **Keys → Add Key → Create new key → JSON → Create**
3. Download the `.json` file

> NEVER commit this JSON file to Git.

### 2.4 Extract Values for `.env`

From the downloaded JSON key file, extract:
- `project_id` → `GOOGLE_CLOUD_PROJECT_ID`
- `client_email` → `GOOGLE_CLOUD_CLIENT_EMAIL`
- `private_key` → `GOOGLE_CLOUD_PRIVATE_KEY`

## Part 3 — Firebase Setup

### 3.1 Create a Firebase Project

1. Go to https://console.firebase.google.com
2. Click **Add project** → select your existing GCP project
3. Create project

### 3.2 Enable Google Authentication

1. Firebase Console → **Authentication → Sign-in method**
2. Enable **Google** provider → Save

### 3.3 Register a Web App

1. Firebase Console → **Project Settings → Your apps → Add app → Web**
2. Register the app (nickname: `kira-web`)
3. Copy the `firebaseConfig` values for frontend `.env.local`

### 3.4 Firebase Admin SDK Key for Backend

1. Firebase Console → **Project Settings → Service Accounts**
2. Click **Generate new private key** → download
3. Extract `project_id`, `client_email`, `private_key` for backend `.env`

### 3.5 Enable Firestore

1. Firebase Console → **Firestore Database → Create database**
2. Start in **production mode**
3. Choose a region

**Firestore Security Rules:**
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /fileMetadata/{fileId} {
      allow read, write: if false; // Backend Admin SDK bypasses these rules
    }
  }
}
```

## Part 6 — API Reference

All endpoints require: `Authorization: Bearer <Firebase ID Token>`

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | /health | Health check (no auth) |
| POST | /api/storage/upload | Upload file through backend (multipart) |
| POST | /api/storage/signed-upload-url | Get signed PUT URL for direct GCS upload |
| POST | /api/storage/confirm-upload | Register metadata after direct upload |
| GET | /api/storage/files | List user's files (?category=images) |
| GET | /api/storage/download/:fileId | Get signed download URL |
| GET | /api/storage/stream/:fileId | Stream file through backend |
| DELETE | /api/storage/:fileId | Delete file from GCS + Firestore |

## Part 8 — File Organization in GCS

```
users/{userId}/{category}/{uuid}-{sanitized-filename}

Examples:
  users/abc123/images/f47ac10b-photo.jpg
  users/abc123/documents/8b0a2-report.pdf
  users/abc123/videos/3c4d5e-recording.mp4
```

## Part 9 — Production Deployment Checklist

- [ ] NODE_ENV=production on backend
- [ ] CORS_ALLOWED_ORIGINS set to production domain only
- [ ] GCS bucket has public access prevention enforced
- [ ] Firestore rules deny direct client access to fileMetadata
- [ ] Service account has only necessary roles (least privilege)
- [ ] No service account JSON files in Git
- [ ] No private keys in frontend code
- [ ] HTTPS enforced on backend and frontend
- [ ] Signed URL expiration times reviewed
- [ ] Rate limiting tuned for production traffic

### Application Default Credentials (ADC) on GCP

If deployed on Cloud Run / App Engine / GKE, leave `GOOGLE_CLOUD_CLIENT_EMAIL` and `GOOGLE_CLOUD_PRIVATE_KEY` empty. The SDK automatically uses ADC — no key file needed.

## Part 10 — Security Model Summary

| Concern | Mitigation |
|---------|-----------|
| Credentials on frontend | Never — only public Firebase config on frontend |
| Private key in Git | Blocked by .gitignore patterns |
| Unauthenticated access | requireAuth middleware on all storage routes |
| Cross-user file access | Ownership check before download/delete |
| Malicious filenames | sanitizeFilename() strips path traversal |
| Oversized files | 500 MB limit at multer + GCS service layer |
| Unsupported file types | MIME type allowlist in gcsService.js |
| Public bucket | Public access prevention enforced |
| Signed URL lifetime | Upload: 15 min — Download: 60 min |
| CORS | Only configured origins allowed |
| Rate limiting | 20 uploads/min per IP |
